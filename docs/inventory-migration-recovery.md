# 商店库存迁移与恢复

## 为什么插件会暂停库存操作

旧版 `npcs.yml` 没有 `inventory-format` 时，同一店主在多个世界的库存副本可能是旧版本复制出的共享库存，也可能是 1.4.0 起各世界独立后恰好相同的合法库存。仅凭内容相同无法判断哪一种。因此，迁移会保留这些 NPC 行中的全部库存，写入人工核账标记，不自动合并或清空。若同一世界多个 NPC 的库存副本不同，也会标记核账，因为旧数据无法安全聚合。

待核账期间，该店主的商店交易、库存编辑、NPC 移动和删除会暂停；其他未受影响的 NPC 可继续使用。服务器日志会列出店主 UUID、涉及世界，以及迁移创建的原始文件备份路径。若默认备份名已存在且内容不同，新备份会使用带后缀的文件名。

## 人工核账步骤

1. 停止服务器，并将整个 `plugins/PhilosNPC/` 目录复制到安全位置。保留当前 `npcs.yml`、`npcs.yml.bak-v1-inventory` 及所有带后缀的同前缀备份。
2. 查看服务器日志，确认待核账店主 UUID、涉及世界和迁移备份的实际路径。
3. 对照当前 `npcs.yml`、迁移备份及其他可信备份，逐世界判断应保留的库存。只修正相关 NPC 行的 `shopInventory`：同一店主同一世界的 NPC 库存应一致，不同世界可各自保留不同库存；不要覆盖其他 NPC 字段、收购背包或转移仓库。
4. 确认所有相关库存都已逐世界修正后，只移除 `inventory-migration-review` 列表中该店主的记录，保留 `inventory-format: 2`。若仍不能确定某世界的正确库存，就保留标记，不要恢复交易。
5. 启动服务器并查看日志，再分别检查涉及世界的商店库存和交易结果。保留修复前的完整目录副本，直到确认数据无误。

迁移备份是迁移当时的整份 `npcs.yml` 快照。迁移后发生的新交易不会写入该备份；**不要把整份备份直接覆盖到当前文件**，否则可能回滚较新的库存、NPC 编辑和交易。只把备份作为逐行核账的来源。

## 先前已清空库存的情况

若此前的迁移已经把库存写成空数组并保存了 `inventory-format: 2`，本次代码无法从当前文件判断原库存，也不会自动从旧文件恢复。停服备份当前完整数据目录，再从可信备份和交易记录人工逐世界核账。不要直接用旧 `npcs.yml` 替换当前文件，以免覆盖后来产生的数据。
